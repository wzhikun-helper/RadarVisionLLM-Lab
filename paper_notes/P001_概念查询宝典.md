# 一、雷达硬件与信号处理基础

## 1. 什么是雷达（Radar）

Radar 全称 **Radio Detection and Ranging**，中文译为 **无线电探测与测距**。其基本工作流程为：发射电磁波 → 电磁波遇到目标后发生反射/散射 → 雷达接收回波 → 分析回波，获得距离、速度、方向等信息。

### Radar 与 Camera 的核心区别

- **Camera（相机）** 主要接收环境中的可见光，擅长获取外观、颜色、纹理、类别等语义信息。
- **Radar（雷达）** 主动发射电磁波并分析反射回波，擅长获取距离、速度、角度、反射强度等物理信息。

> **Camera 更擅长"这是什么"，Radar 更擅长"它在哪里、怎么运动"。**

---

## 2. 电磁波（Electromagnetic Wave）

雷达发射的是 **电磁波**

### 频率（Frequency）

频率表示电磁波每秒振荡的次数，常用单位为 Hz、kHz、MHz、GHz。例如 77 GHz 表示每秒约 770 亿次振荡。先把电磁波简化成一条上下起伏的波：

```text
振幅
  ^
  |
  |        /\        /\        /\
  |       /  \      /  \      /  \
  |      /    \    /    \    /    \
  |-----/------\--/------\--/------\------> 时间
  |    /        \/        \/        \
  |
```

一个完整的"起伏"就是 **一次振荡**，也就是 **一个周期（period）**。下面标出 3 次完整振荡：

```text
振幅
  ^
  |
  |        /\        /\        /\
  |       /  \      /  \      /  \
  |      /    \    /    \    /    \
  |-----/------\--/------\--/------\------> 时间
        <----1----><----2----><----3---->
          一次振荡   一次振荡   一次振荡
```

如果这 3 次振荡刚好发生在 1 秒内，则：

$$f = 3\text{ Hz}$$

即 **1 秒振动了 3 次**。

#### 低频 vs 高频

**低频（1 秒内振得少）：**

```text
振幅
  ^
  |
  |        /\                /\
  |       /  \              /  \
  |      /    \            /    \
  |-----/------\----------/------\------> 时间（1秒）
```

假设这 1 秒里只有 2 次振荡，则：

$$f = 2\text{ Hz}$$

**高频（1 秒内振得快、振得多）：**

```text
振幅
  ^
  |
  |     /\  /\  /\  /\  /\  /\  /\
  |    /  \/  \/  \/  \/  \/  \/  \
  |---/------------------------------> 时间（1秒）
```

假设这 1 秒里有 7 次振荡，则：

$$f = 7\text{ Hz}$$

### 波长（Wavelength）

波长与频率的关系为：

$$
\lambda = \frac{c}{f}
$$

其中 $\lambda$ 是波长，$c$ 是光速，$f$ 是频率。**频率越高 → 波长越短。** ==77 GHz 级雷达的波长只有几毫米，因此被称为 **毫米波雷达（Millimeter‑Wave Radar）**。==

## 3. 回波（Echo）

电磁波遇到目标后可能出现反射、散射或吸收。雷达真正使用的是 **返回接收天线的那部分能量**，即 **回波（Echo）**。通过分析回波可获得以下信息：

- **回波时延 → 距离**：设发射时间为 $t_1$，收到回波时间为 $t_2$，传播时间 $\Delta t = t_2 - t_1$。电磁波速度为 $c$，总路程为 $c\Delta t$。由于电磁波走了 **雷达→目标→雷达** 一个来回，因此目标实际距离为：

$$
R = \frac{c\Delta t}{2}
$$

除以 2 是因为测量的是往返路程，而我们需要的是单程距离。

- **频率变化 → 多普勒速度**
- **不同天线间的相位差 → 角度**
- **回波强弱 → RCS / 反射强度**

---

## 4. FMCW、Chirp 与 Beat Frequency

### FMCW（调频连续波）

汽车毫米波雷达的探测距离通常为几十到几百米，电磁波往返时间极短。若直接测量 $\Delta t$，需要极高的时间分辨率和昂贵的硬件。因此现代车载毫米波雷达广泛采用**FMCW（Frequency Modulated Continuous Wave，调频连续波）** 体制。其核心思想是：**不直接测量极短的时间差，而是将时间延迟转换为更容易测量的频率差。**

### Chirp（啁啾信号）

FMCW 雷达会连续发射频率随时间变化的信号，最常见的是 **线性上升 Chirp**：

```text
频率 f
  ^
  |
  |                         /
  |                      /
  |                   /
  |                /
  |             /
  |          /
  |       /
  |    /
  | /
  +----------------------------------> 时间 t
```

一开始频率较低，随着时间推移，频率逐渐升高，这一整段线性上升信号就是一个 Chirp。

实际雷达通常会连续发射多个 Chirp：

```text
频率 f
  ^
  |
  |        /|        /|        /|
  |       / |       / |       / |
  |      /  |      /  |      /  |
  |     /   |     /   |     /   |
  |    /    |    /    |    /    |
  |___/_____|___/_____|___/_____|____> 时间 t
   Chirp 1   Chirp 2   Chirp 3
```

雷达发出的 Chirp 打到目标再返回：

```text
Radar  --------------------->  Target
       <---------------------
```

因为电磁波传播需要时间，所以回波是 **延迟后的发射信号副本**。

**发射 Chirp（Tx）与回波信号（Rx）的对比：**

```text
频率 f
  ^
  |
  |                           /   ← 发射信号 Tx
  |                        /
  |                     /
  |                  /
  |               /
  |            /
  |         /      ← 回波信号 Rx（整体向右平移了 τ）
  |      /
  |   /
  |/
  +--------------------------------------> 时间 t
                <---- τ ---->
```

- **Tx**：当前发射信号
- **Rx**：回波信号
- **$\tau$**：传播时延（Propagation Delay）

回波信号就是发射信号的"延迟副本"，整体在时间轴上向右平移了 $\tau$。==目标越远，$\tau$ 越大，回波信号向右偏移越多==。

Chirp 频率变化的快慢称为 **斜率（Slope）**：

$$
S = \frac{B}{T}
$$

其中 $B$ 为带宽，$T$ 为 Chirp 持续时间。在相同距离（相同 $\tau$）下，斜率越大，拍频 $f_b$ 越大。

### Beat Frequency（拍频）

目标越远，传播延迟 $\tau$ 越大；接收到的回波是更早发出的 Chirp 信号；当前发射信号与回波信号的瞬时频率差越大——这个频率差即为 **拍频（Beat Frequency）**，记为 $f_b$。

```text
频率 f
  ^
  |
  |                           /   ← Tx
  |                        /
  |                     /     ↑
  |                  /        │
  |               /           │ fb
  |            /              │
  |         /   ← Rx          ↓
  |      /
  |   /
  |/
  +--------------------------------------> 时间 t
```

若 Chirp 斜率为 $S$，则有：

$$
f_b = S\tau, \quad \tau = \frac{2R}{c}
$$

进而：

$$
R = \frac{c f_b}{2S}
$$

==核心理解：**距离 → 时延 → 频率差 → 拍频**，即距离信息被转换成了频率信息==。

> 距离越远 → 传播时延 $\tau$ 越大 → Rx Chirp 滞后越多 → 同一时刻 Tx / Rx 的频率差越大 → Beat Frequency $f_b$ 越大 → 由 $f_b$ 反推距离。

## ==5. 多普勒效应（Doppler Effect）==

当目标与雷达之间存在相对运动时，雷达接收到的回波频率会相对于发射频率发生变化，这种现象称为 **多普勒效应（Doppler Effect）**。

最直观的生活例子是救护车：当救护车朝你靠近时，警笛声更尖（频率升高）；当救护车远离时，声音变低（频率降低）。其本质是：**相对运动改变了观察者接收到的波的频率。**雷达中使用的是电磁波，道理相同。

### 汽车静止时

```text
Radar  ))))))))))))))  Car
       ←------------→
```

目标与雷达之间的距离基本不变，连续返回的波峰之间的间隔也基本保持不变，因此不会产生明显的多普勒频移。

### 汽车朝雷达靠近时

```text
                 ← ← ← Car
Radar ●  )))))))))))))
```

汽车不断缩短与雷达之间的距离，返回雷达的波峰被"挤"得更密了：

```text
静止时：
|      |      |      |      |
波峰   波峰   波峰   波峰

靠近时：
|   |   |   |   |   |
波峰之间更密
```

单位时间内到达雷达的波峰数量增多，因此 **接收到的频率升高**。

### 汽车远离雷达时

```text
Radar ●                 Car → → →
       )))))))))))))
```

连续返回的波峰之间变得更加分散，单位时间内到达雷达的波峰数量减少，因此 **接收到的频率降低**。

```text
目标靠近 → 回波波峰更密 → 频率升高
目标远离 → 回波波峰更疏 → 频率降低
```

### 多普勒频移（Doppler Frequency）

雷达发射频率记为 $f_c$。由于目标运动，接收到的回波相对于原频率产生了一个小的变化量，这个频率变化量即 **多普勒频移（Doppler Frequency / Doppler Shift）**，记作 $f_d$。

简单来说：**==多普勒频移 = 目标运动造成的频率偏移量。==** 例如发射 77 GHz，目标运动使回波变为 77 GHz 加一个很小的频率偏移。实际的 $f_d$ 相对于 77 GHz 载波通常非常小，但信号处理可以将其提取出来。

对于单基地雷达，常见关系为：

$$
f_d = \frac{2v_r}{\lambda}
$$

其中 $f_d$ 为多普勒频移，$v_r$ 为径向速度，$\lambda$ 为雷达信号波长。核心理解是：**在波长一定时，径向速度越大，多普勒频移越大。**信号一去一回，目标运动对去程和回程都会产生影响，因此单基地雷达的多普勒关系中会出现系数 2。

### 径向速度（Radial Velocity）

雷达并不能通过一次多普勒测量直接知道汽车的完整二维或三维速度。它直接感知的是：**目标沿雷达—目标连线方向（Line of Sight, LOS）靠近或远离的速度。** 这一部分速度叫 **径向速度（Radial Velocity）**。

```text
Radar ● ---------------------- ● Car
```

这条雷达到目标的连线就是视线方向（LOS），多普勒最直接反映的就是目标沿着这条线运动得有多快。

#### 情况一：汽车直接朝雷达运动

```text
               v
        ← ← ← ← ←
Radar ● ---------------- ● Car
```

汽车运动方向与视线方向基本一致，所有速度几乎都贡献给了径向速度：$v_r \approx v$。例如汽车真实速度 $v = 10\text{ m/s}$，雷达测得的径向速度大小也接近 $|v_r| = 10\text{ m/s}$。**正对雷达开过来或离开时，多普勒最明显。**

#### 情况二：汽车完全横向经过

```text
                  ↑
                  ↑ v
                  ↑
                  ● Car
                  |
                  |
Radar ● ----------+
      LOS
```

雷达—目标连线是水平方向，汽车运动方向是竖直方向，二者夹角 $\theta = 90^\circ$。汽车虽然真实速度可能为 $v = 20\text{ m/s}$，但它此刻既没有靠近也没有远离雷达，因此 $v_r = 0,\ f_d \approx 0$。**这就是为什么汽车明明运动得非常快，但雷达测到的多普勒仍然可能接近零。**

#### 情况三：汽车斜着运动（最常见的情况）

```text
                     ↗ v
                   /
                 / θ
               /
Radar ● -------------------- ● Car
             LOS
```

汽车真实速度 $v$ 可以拆成两个分量：沿视线方向的部分就是径向速度 $v_r$，其余为横向速度分量：

```text
                     ↗ v
                   / |
                 /   |
               /     |  横向速度分量
             /       |
Radar ● ----→--------●
          vr
       径向速度
```

因此：

$$
v_r = v\cos\theta
$$

其中 $\theta$ 是**目标真实运动方向与雷达视线方向之间的夹角**（不是目标速度与雷达运动方向的夹角——雷达本身可以完全静止）。

```text
θ 越小 → 径向速度越大 → 多普勒越明显
θ 越接近 90° → 径向速度越小 → 多普勒越弱
```

#### 重要认识

假设雷达测到 `Radial Velocity = 5 m/s`，不能直接说"这辆车真实速度就是 5 m/s"。它真正表示的是：**这辆车沿雷达视线方向的速度分量是 5 m/s，实际速度可能是 5 m/s、8 m/s、10 m/s 甚至更高**，取决于目标运动方向。这是以后处理雷达数据时必须特别注意的一点。
==Doppler 反映的是目标沿 LOS 方向距离变化的快慢，而不是完整二维/三维速度。==
此外，仅知道 $|v_r| = 5\text{ m/s}$ 还不够，因为存在两种可能：

- **靠近雷达** → 距离越来越小
- **远离雷达** → 距离越来越大

因此雷达通常使用正负号区分运动方向。例如某系统可能规定 `+5 m/s = 远离`，`-5 m/s = 靠近`，但另一个系统完全可能反过来定义。**多普勒正负号不是世界统一的——取决于每个系统的符号约定（Sign Convention）。**

因此以后使用任何雷达数据集时，都应检查：

- 多普勒符号约定（Doppler sign convention）
- 径向速度约定（Radial velocity convention）
- 坐标系定义（Coordinate system）

## 6. 角度测量

雷达需获取目标的 **方位角（Azimuth，左右方向）** 和 **俯仰角（Elevation，上下方向）**。

单个接收天线只能感知回波的存在，难以精确判断来波方向。雷达通常采用 **天线阵列（Antenna Array）**：目标从非垂直方向入射时，不同天线接收信号的波程差会导致 **相位差（Phase Difference）**，雷达通过相位差估计 **到达角（Angle of Arrival, AoA）**。

## 7. 雷达散射截面（RCS）

RCS 全称 **Radar Cross Section**，中文译为 **雷达散射截面**。

> **一个目标把雷达电磁波散射回雷达方向的能力有多强。可以简单理解为这个目标在雷达"眼里"有多显眼。**

雷达发射电磁波后，目标会把一部分能量反射回来：

```text
Radar  ─────────────→ Target
       ←─────────────
            Echo
```

有的目标返回的能量强，有的弱——RCS 就与这种反射/散射能力密切相关。

### RCS 不等于物体实际大小

这是一个非常重要的概念。不能简单认为物体越大、RCS 就越大。RCS 受到多种因素影响：

- 目标尺寸（Target Size）
- 材料（Material）
- 形状（Shape）
- 朝向（Orientation）
- 雷达观察角度（Observation Angle）
- 雷达频率（Radar Frequency）

> **RCS 描述的是"电磁散射意义上的大小"，而不是简单的物理尺寸。**

### 朝向对 RCS 的影响

以同一块金属板为例：

**正对雷达时：**

```text
Radar ───────→ | Metal Plate
      ←========
        强回波
```

较多电磁能量被反射回雷达，RCS 可能较大。

**金属板倾斜时：**

```text
Radar ───────→ /
               ↗
         能量被反射到其他方向
```

虽然还是同一块金属板，但返回雷达的能量明显降低。因此：**同一个目标，仅仅改变朝向，雷达接收到的回波强度就可能发生很大变化。**

### 为什么汽车通常容易产生较强雷达回波？

汽车具有很多有利于电磁散射的结构，例如金属车身、保险杠、轮毂、底盘、车身边缘以及各种金属角结构，因此通常会产生多个明显的散射中心：

```text
        Car
   ┌─────────────┐
   │ ●        ●  │
   │     ●       │
   │ ●        ●  │
   └─────────────┘
```

这些位置都可能产生较强回波。

## 8. 雷达点云（Radar Point Cloud）

### 什么是 Radar Point Cloud？

雷达经过信号处理后，通常会得到一组离散的检测点，这些点的集合称为 **雷达点云（Radar Point Cloud）**：

```text
        ●
   ●        ●

       ●

 ●           ●
```

每个点可以理解为一个雷达检测到的有效散射位置。

### 为什么 Radar Point Cloud 比 LiDAR 稀疏？

雷达并不是在目标表面的每个位置都会产生一个稳定的检测点。只有回波足够强、并且通过了检测算法阈值的散射位置，才会最终形成雷达点：

```text
真实目标表面
      ↓
只有部分位置产生较强散射
      ↓
经过检测算法
      ↓
保留部分有效点
      ↓
Radar Point Cloud 比较稀疏
```

### Radar 与 LiDAR 点云的直观对比

**LiDAR** 主动使用激光扫描物体表面，因此很多表面位置都可以形成测量点，点通常较密，几何轮廓更明显：

```text
● ● ● ● ● ● ●
● ● ● ● ● ● ●
● ● ● ● ● ● ●
```

**Radar** 只在部分有效散射位置形成点，点云通常更稀疏、更不规则：

```text
●          ●

      ●

          ●
```

但 Radar point 往往具有 LiDAR 所不具备的一项重要优势：==**多普勒/径向速度（Doppler / Radial Velocity）信息。**==

### 一个 Radar Point 里通常有什么？

例如一个点包含以下信息：

```text
Point 1
x = 12.3 m
y = 1.8 m
z = 0.6 m
Radial Velocity = -4.2 m/s
RCS = 9 dBsm
```

- **x, y, z**：这个点在哪里
- **Radial Velocity**：这个点沿雷达视线方向怎么运动
- **RCS**：这个点的电磁散射强度有多大

关于坐标系：Radar point 通常会被转换到某一个坐标系中，例如某些自动驾驶数据集可能规定 `x → 前方`、`y → 左右`、`z → 上下`。但是**不同雷达、不同数据集的坐标定义可能不同**，因此处理具体数据集时必须先查看坐标系定义、坐标轴方向和正方向规定。

### 为什么 Radar Point Cloud 看起来可能很"乱"？

雷达点不一定都来自目标主体，也可能来自车身、保险杠、轮毂、地面、护栏、墙体、静态背景、多径反射以及杂波等各种来源：

```text
      ●          ← 车身散射点
   ●
        ●

----------------
 ●      ●       ← 地面 / 杂波点
```

因此 Radar Point Cloud 不一定像相机图像或 LiDAR 那样容易直接看懂。这也是后面需要继续学习 Clutter、Multipath、CFAR 和 Point Cloud Generation 的原因。

### Radar Point 的核心优势

普通三维点可能只有 `x`、`y`、`z`，而 Radar point 常常还具有 **多普勒/径向速度**（**多普勒（Doppler / Doppler frequency）** 是原始层面的信息，即雷达从 Chirp 间的相位变化中提取出来的频率偏移 𝑓𝑑。**径向速度（Radial velocity）** 是从多普勒频移换算出来的物理速度 𝑣𝑟）。因此雷达不仅能告诉我们"这个点在哪里"，还能告诉我们"这个点沿雷达视线方向怎么运动"。这对于自动驾驶、运动目标检测和雷达-相机融合非常重要。
结合实际使用，这三个词经常被混着说：

|说法|实际指的通常是|
|:--|:--|
|"这个点的多普勒"|多普勒频移 𝑓𝑑 或据此换算出的径向速度 𝑣𝑟|
|"多普勒偏移"|精确指频率变化量 𝑓𝑑，单位 Hz|
|"测到的多普勒速度"|已经把 𝑓𝑑 换算成 𝑣𝑟，单位 m/s|

## 9. 3D 雷达与 4D 雷达

### 基本理解框架

一个雷达检测点可以从四个维度来理解：

- **Range**：多远？
- **Azimuth / Elevation（Angle）**：在哪个方向？
- **Doppler / Radial Velocity**：沿雷达视线方向怎么运动？
- **RCS**：对雷达来说反射有多强？

即：**Range → 多远？Angle → 在哪？Doppler → 怎么动？RCS → 有多"显眼"？**

### 3D Radar 与 4D Radar 的定义

在自动驾驶雷达语境中，**4D Radar** 通常不是指"四维时空"。常见的四个测量维度是：

```text
Range + Azimuth + Elevation + Doppler / Radial Velocity
```

即：**距离 + 水平角 + 垂直角 + 径向速度。**

很多传统车载雷达主要能够较好地测量 Range（距离）、Azimuth（水平角）和 Doppler（多普勒速度），即"多远 + 左右方向 + 靠近/远离速度"。但是对 **Elevation（俯仰角）** 的分辨能力通常比较弱，因此不太容易准确判断回波到底来自地面、车辆下部还是车辆更高的位置。

==4D Radar 一个非常重要的特点是：**更加精确的 Elevation / 垂直方向测量能力。**== 因此它能更完整地获取目标空间信息——Range + Azimuth + Elevation + Doppler，最终可以进一步转换为 `x`、`y`、`z`、`velocity`。

为什么 Elevation 很重要？假设从俯视图看，两个反射点几乎处于相同位置：

```text
Top View
Radar ● ---------- ●
```

但实际可能一个来自车辆、一个来自地面。从侧面看：

```text
        ●  ← 车辆反射点

Radar ●

        ●  ← 地面反射点
```

如果缺少 Elevation 信息，就很难区分。因此更准确的高度信息有助于：

- 3D 目标检测
- 雷达点云理解
- 雷达-相机融合
- 地面/目标分离

> **注意**：在不同研究领域，"4D" 可能有不同含义。例如某些视觉或医学领域中 `x + y + z + time` 也会被称为 4D。但在自动驾驶 4D Radar 中，通常更多指 **3D 空间信息 + 多普勒速度**。因此看论文时不能只看名称，必须阅读作者对 4D Radar 的具体定义。

### 4D Radar Point Cloud 的特点

由于 4D Radar 通常具备更好的距离分辨率、方位角分辨率、俯仰角分辨率以及更强的天线阵列能力，其点云通常比传统低分辨率汽车雷达更丰富：

- 传统 Radar：点很少，稀疏分布
- 高分辨率 4D Radar：点更多、更密

但即使 4D Radar 点云越来越密，一般仍不能简单等同于 LiDAR point cloud——两者的核心优势依然不同：

- **LiDAR** 的核心优势：几何结构（Geometry）
- **Radar** 的核心优势：**运动信息 + 物理测量 + 恶劣环境鲁棒性**，尤其是多普勒速度是雷达非常独特且有价值的信息

### 雷达-相机融合的互补关系

Camera 可以提供物体类别、外观、纹理、语义信息（例如"这是一辆汽车"），而 Radar 可以提供距离、三维位置、径向速度、RCS（例如"这个散射点位于 22 m 处，正在以某个径向速度运动"）。因此雷达-相机融合的核心互补关系可以理解为：

> **Camera → 语义信息（Semantic Information）**
> **Radar → 物理信息（Physical Information）**
> **Camera + Radar → 语义 + 物理感知（Semantic + Physical Perception）**
## 10. Range-Doppler Map（距离-多普勒图）

Range-Doppler Map 是一种二维雷达表示方法，用于同时描述目标的 **距离** 和 **径向速度**。通常可以理解为：

- **横轴**：Range / 距离
- **纵轴**：Doppler / Radial Velocity / 径向速度

```text
Radial Velocity
      ↑
 +5   |        ● A
      |
  0   |              ● C
      |
 -3   |        ● B
      |
      +------------------------→ Range
               20 m    30 m
```

- **A**：20 m，+5 m/s
- **B**：20 m，−3 m/s
- **C**：30 m，0 m/s

每一个亮点可以理解为：**在某个距离和某个径向速度位置存在较强雷达回波。**

如果只看距离：

```text
20 m 有目标
30 m 有目标
```

无法进一步判断这些目标如何运动。加入 Doppler 信息后，可以同时知道目标在哪里以及目标沿雷达视线方向如何运动，即 **Position + Motion**。

### 相同距离、不同速度的目标可以分开

例如 Target A（20 m, +5 m/s）和 Target B（20 m, −3 m/s），两个目标距离相同，但 Doppler 不同：

```text
Velocity
  ↑
+5|        ● A
  |
-3|        ● B
  |
  +--------------------→ Range
           20 m
```

在 Range-Doppler Map 上仍然可以区分开。同理，相同速度但距离不同的目标，也可以通过 Range 维度分开。

### 为什么会形成 Range-Doppler Map？

雷达通常先做 Range FFT 得到距离维，再做 Doppler FFT 得到速度维，于是得到二维结果：

```text
Range × Doppler
```

即 Range-Doppler Map。

```text
Raw Radar Signal
      ↓
  Range FFT
      ↓
Range Information
      ↓
 Doppler FFT
      ↓
Range-Doppler Map
```

## 11. Range-Azimuth Map（距离-方位角图）

Range-Azimuth Map 也是二维雷达表示，通常：

- **一个维度**：Range
- **另一个维度**：Azimuth

它回答两个问题：**目标有多远？目标在左边还是右边？**

例如 Target A（20 m, −20°）和 Target B（20 m, +25°），虽然它们距离相同，但左右方向不同，因此在 Range-Azimuth Map 中可以区分。

### Range-Doppler 与 Range-Azimuth 的区别

| 表示方式              | 第一个维度 | 第二个维度   | 主要回答的问题    |
| :---------------- | :---- | :------ | :--------- |
| Range-Doppler Map | Range | Doppler | 多远、怎么动     |
| Range-Azimuth Map | Range | Azimuth | 多远、在哪个左右方向 |

因此雷达可以从多个维度理解目标：

```text
Range     → 多远
Doppler   → 怎么动
Azimuth   → 左右哪里
Elevation → 上下哪里
RCS       → 回波有多强
```

## 12. FFT（Fast Fourier Transform，快速傅里叶变换）

雷达原始回波并不会直接给出"20 m、5 m/s、右偏 10°"这样的结果——它得到的是随时间变化的电信号。因此必须通过信号处理，==把目标对应的信息从混合信号中提取出来==。其中最重要的工具之一就是 **FFT（Fast Fourier Transform，快速傅里叶变换）**。

### FFT 最直观的理解

> **把一个复杂信号拆成其中包含的不同频率成分。**

```text
复杂信号=频率 1 + 频率 2 + 频率 3 + ...
```

经过 FFT：

```text
混合信号
   ↓
  FFT
   ↓
不同频率成分
```

就像把混合声音中的不同音调分开。前面已经学过，FMCW 会把距离信息转换成 Beat Frequency：

```text
Distance → Time Delay → Beat Frequency
```

==不同距离的目标（如 10 m 和 25 m）会产生不同的 Beat Frequency==。如果这些回波混在一起：

```text
Echo = Frequency A + Frequency B
```

雷达就可以通过 FFT 把它们分开。

假设 FFT 后得到：

```text
Amplitude
   ↑
   |        ▲
   |        │
   |   ▲    │
   |   │    │
   |___│____│____________→ Frequency
       f1   f2
```

其中 $f_1$ 和 $f_2$ 是两个主要频率成分。如果 $f_1$ 对应 Target A，$f_2$ 对应 Target B，那么两个峰就对应两个不同距离的目标。因此：

> **FFT 可以帮助雷达从混合回波中找出不同目标对应的频率成分。**

---

### 三种 FFT 的作用

#### Range FFT（距离 FFT）

Range FFT 的主要作用：**把不同距离的目标分开。**

```text
FMCW 回波
   ↓
得到 Beat Frequency
   ↓
Range FFT
   ↓
找到不同频率峰
   ↓
转换为不同 Range
```

因为不同距离 → 不同时间延迟 → 不同 Beat Frequency，所以通过分析 Beat Frequency 就可以估计距离。

> **Range FFT = 分距离**

Range FFT 只能告诉我们在某个距离附近存在较强目标回波，但还不能完整告诉我们目标怎么运动。因此还需要 **Doppler FFT**。

#### Doppler FFT（多普勒 FFT）

雷达通常不会只发一个 Chirp，而是连续发射很多 Chirp：

```text
Chirp 1 → Chirp 2 → Chirp 3 → Chirp 4 → Chirp 5 → ...
```

如果目标在运动，相邻 Chirp 之间的回波相位会发生规律变化。雷达对多个 Chirp 之间的变化进行处理：

```text
多个 Chirp
   ↓
观察相位随 Chirp 的变化
   ↓
Doppler FFT
   ↓
Doppler Frequency
   ↓
Radial Velocity
```

> **Doppler FFT = 分速度**

#### Angle FFT（角度 FFT）

除了距离和速度，我们还希望知道目标来自哪个方向。雷达使用多个接收天线，不同天线之间存在 **相位差（Phase Difference）** 利用这些相位差可以估计目标来波方向。一种常见方法就是 **Angle FFT**。

> **Range FFT：分距离**
> **Doppler FFT：分速度**
> **Angle FFT：分方向**


#### 雷达信号处理的初步总流程

```text
Raw Radar Signal
      ↓
  Range FFT
      ↓
    Range
      ↓
 Doppler FFT
      ↓
   Velocity
      ↓
Angle Estimation / Angle FFT
      ↓
Azimuth / Elevation
```

最终雷达可以得到 **Range、Doppler、Azimuth、Elevation、RCS**，然后进一步形成 **Radar Point Cloud**。

## 13. ADC Data（原始数字采样数据）

雷达天线接收到的回波首先是连续变化的模拟电信号。计算机不能直接处理连续模拟信号，因此需要通过 **ADC（Analog-to-Digital Converter，模数转换器）** 将模拟信号转换成数字序列。

基本过程：

```text
发射 Chirp
   ↓
目标反射
   ↓
接收回波
   ↓
混频得到 Beat Signal
   ↓
ADC 采样
   ↓
数字数据
   ↓
后续 FFT 处理
```

**Beat Frequency（$f_b$）是频率差，而 Beat Signal 是混频后得到的那个时域信号本身。**

### ADC 采样

假设 Beat Signal 是连续变化的波形：

```text
Amplitude
  ^
  |       /\
  |      /  \      /\
  |_____/    \____/  \____
  +-----------------------> time
```

ADC 会每隔一个很短的时间读取一次信号幅值：

```text
●   ●   ●   ●   ●   ●   ●
```

于是形成一串数字序列：

```text
Sample 1, Sample 2, Sample 3, Sample 4, ...
```

因此可以简单理解：

> **ADC 的作用是把连续的模拟雷达信号，变成计算机能够处理的一串数字。**

---

## 14. Fast Time（快时间）与 Slow Time（慢时间）

### Fast Time（快时间）

雷达发射一个 Chirp 时，ADC 会在这个 Chirp 内连续采很多点：

```text
Chirp 1

● ● ● ● ● ● ● ● ● ● ● ●
```

这些 **一个 Chirp 内部的连续 ADC Samples** 构成 **Fast Time（快时间）**。之所以叫快时间，是因为 ADC 在一个很短的 Chirp 时间内高速采样。

前面已经学过：不同距离的目标会产生不同的 Beat Frequency，而这些 Beat Frequency 就体现在一个 Chirp 内的采样信号中。因此：

```text
一个 Chirp 内 ADC Samples
        ↓
    Fast Time
        ↓
    Range FFT
        ↓
  Beat Frequency
        ↓
       Range
```

> **Range FFT 是沿 Fast Time 方向进行的。**

---

### Slow Time（慢时间）

雷达不会只发一个 Chirp，通常会连续发很多个：

```text
Chirp 1 → Chirp 2 → Chirp 3 → Chirp 4 → Chirp 5 → ...
```

每个 Chirp 内都有很多 ADC Samples，因此整个数据可以理解成一个二维结构：

```text
                Fast Time →
             ADC Samples

          s1  s2  s3  s4  s5
Chirp 1   ●   ●   ●   ●   ●
Chirp 2   ●   ●   ●   ●   ●
Chirp 3   ●   ●   ●   ●   ●
Chirp 4   ●   ●   ●   ●   ●
   ↓
Slow Time
```

纵向不同 Chirp 之间的序列就是 **Slow Time（慢时间）**。

==如果目标发生运动，相邻 Chirp 接收到的回波相位会逐渐发生规律变化==：

```text
Chirp 1 → phase = φ1
Chirp 2 → phase = φ2
Chirp 3 → phase = φ3
Chirp 4 → phase = φ4
```

这种相位随 Chirp 的变化与目标运动有关。因此：

```text
多个 Chirp
   ↓
Slow Time
   ↓
Doppler FFT
   ↓
Doppler Frequency
   ↓
Radial Velocity
```

> **Doppler FFT 是沿 Slow Time 方向进行的。**

---

### Fast Time 与 Slow Time 的核心区别

| 概念        | 表示什么                    | 主要提取的信息            |
| :-------- | :---------------------- | :----------------- |
| Fast Time | 一个 Chirp 内的 ADC Samples | Range              |
| Slow Time | 多个 Chirp 之间的序列          | Doppler / Velocity |

---

## 15. 什么是 Bin？

Bin 可以理解成：**数字信号处理后形成的离散小格子。** 真实世界中的距离和速度是连续的，但计算机只能处理有限数量的采样点，因此最后得到的频率、距离和速度都是离散表示。

### Frequency Bin（频率 Bin）

假设一个 Chirp 内采样了有限个 ADC Samples。经过 FFT 后，不会得到无限连续的频率轴，而是得到有限数量的 Frequency Bins：

```text
| f0 | f1 | f2 | f3 | f4 | ...
```

每一个 Bin 表示一个离散频率区间。

### Range Bin（距离 Bin）

在 FMCW 雷达中，Beat Frequency → Range，因此 Frequency Bin 可以进一步映射为 Range Bin：

```text
Range →
|----|----|----|----|----|
Bin1 Bin2 Bin3 Bin4 Bin5
```

假设每个 Bin 对应 0.15 m：

```text
Bin 1 → 0 ~ 0.15 m
Bin 2 → 0.15 ~ 0.30 m
Bin 3 → 0.30 ~ 0.45 m
...
```

> **Range Bin 是距离轴上的一个离散数字单元。**

#### Range Bin 是怎么产生的？

```text
ADC Samples
   ↓
Range FFT
   ↓
Frequency Bins
   ↓
通过 FMCW 距离关系换算
   ↓
Range Bins
```

==因此雷达并不是直接得到"Target = 20 m"，而是先得到"某个 FFT Bin 存在 Peak"，然后再换算成"Range ≈ 20 m"==。

#### 为什么目标会落在某个 Bin 中？

真实目标距离是连续的（例如 $R = 20.13$ m），但数字雷达的 Range Axis 是离散的（例如 20.0 m, 20.2 m, 20.4 m...），目标最终会落入最接近的 Range Bin 中。这就是 **离散化（Discretization）**。

### Doppler Bin（多普勒 Bin）

Doppler 维度也不是无限连续的：

```text
Velocity
 ↑
+4 m/s
+2 m/s
 0 m/s
-2 m/s
-4 m/s
```

每一个速度格子都可以看作一个 **Doppler Bin**。如果真实目标 $v_r = 3.7$ m/s，它最终会落在某一个最接近的 Doppler Bin 中。

Range-Doppler Map 可以理解成由距离格子和速度格子共同组成的二维能量地图：

```text
                 Range Bin →
            1   2   3   4   5

Doppler 1 |   |   | ● |   |
Bin     2 |   | ● |   |   |
        3 |   |   |   |   |
        4 |   |   |   | ● |
```

每一个格子对应 **一个 Range Bin + 一个 Doppler Bin**，格子中的数值通常表示该距离-速度位置上的回波能量或幅度。

---

## ==16. Range Bin 、 Range Resolution（距离分辨率）、Doppler Resolution（速度分辨率）==

### Range Resolution（距离分辨率）

| 概念                   | 含义                 | 偏向                           |
| :------------------- | :----------------- | :--------------------------- |
| **Range Bin Size**   | 数字处理后，距离轴被切成多细的小格子 | 数字表示（Digital Representation） |
| **Range Resolution** | 雷达真正区分两个相近目标的物理能力  | 物理分辨能力                       |

==距离分辨率主要由 **带宽（Bandwidth）** 决定==：

$$
\Delta R = \frac{c}{2B}
$$

> **Bin 很小，不代表雷达的真实物理分辨能力一定很高。**


可以用 Camera 类比。假设一张图片有很多像素（像素很多），但镜头本身严重模糊，那么即使数字像素非常密，也不代表真正能看清更多细节。雷达同理：

```text
Range Bin 很细
    ≠
一定能区分两个非常接近的目标
```

==真实分辨能力仍然受到 Bandwidth、信号质量等因素的限制==。

---

### Doppler Resolution（速度分辨率）

和 Range 类似，Doppler 也有 **Doppler Resolution**，它表示：**两个径向速度很接近的目标，雷达能不能把它们分开。**

例如 Target A = 5.0 m/s 和 Target B = 5.1 m/s：

- 如果 Doppler Resolution 不够：可能表现成一个目标
- 如果分辨率足够：可以分成两个不同 Doppler Peaks

---

## 17. 距离方向与速度方向流程总结

### 距离方向

```text
一个 Chirp 内 ADC Samples
        ↓
    Fast Time
        ↓
    Range FFT
        ↓
  Frequency Bins
        ↓
    Range Bins
        ↓
       Range
```

### 速度方向

```text
多个 Chirp
        ↓
    Slow Time
        ↓
   Doppler FFT
        ↓
   Doppler Bins
        ↓
  Radial Velocity
```

### 两个方向组合

```text
Range Bin × Doppler Bin → Range-Doppler Map
```

因此可以把 Range-Doppler Map 看作：**一个由距离格子和速度格子共同组成的二维能量地图。**
## 18. Radar Cube（雷达数据立方体）

**Radar Cube** 可以理解成：**把 Range、Doppler 和 Antenna（或 Angle）等多个维度组织在一起的高维雷达数据结构。**

最简单的理解是：

```text
Range × Doppler × Antenna
```

经过角度处理后，也可以进一步理解为：

```text
Range × Doppler × Angle
```

前面学习的 **Range-Doppler Map** 是二维数据：

```text
        Range →
Doppler
   ↓
[ ][ ][ ][ ]
[ ][●][ ][ ]
[ ][ ][ ][●]
[ ][ ][ ][ ]
```

其中每一个格子表示：**某个距离 + 某个径向速度位置上的回波能量。**

如果雷达有多个接收天线（例如 Rx1, Rx2, Rx3, Rx4），每个接收天线都可以对应一份 Range-Doppler 数据。将这些数据沿天线维度堆叠起来，就形成了 **Radar Cube**。

Radar Cube 的核心维度可以理解为：

- **第一维：Range（距离）**
- **第二维：Doppler（多普勒/速度）**
- **第三维：Antenna（接收天线）**

即数据中每个单元对应：某个距离 + 某个速度 + 某个接收天线的回波信息。

例如：

```text
Range Bin = 20
Doppler Bin = 5
Antenna = Rx3
```

表示 Rx3 天线在该距离和 Doppler 位置接收到的回波。

### 为什么需要保留多个天线的数据？

因为角度估计（AoA / Angle Estimation）依赖不同接收天线之间的 **相位差**：

```text
Rx1 → phase φ1
Rx2 → phase φ2
Rx3 → phase φ3
Rx4 → phase φ4
```

利用这些相位差可以估计目标的 **Azimuth（方位角）** 和 **Elevation（俯仰角）**。因此 **Radar Cube 保留多天线数据，正是为了后续的角度估计。**

同时，Radar Cube 中的数据通常不只是回波强度，还保留 **振幅（Amplitude）** 和 **相位（Phase）**，因为相位差在角度估计中是不可或缺的信息。

### Radar Cube 与 Radar Point Cloud 的区别

这是一组非常重要的区别：

- **Radar Cube** 属于较底层、信息量大的雷达数据，包含大量 Range Bins、Doppler Bins、天线信息、振幅和相位。
- **Radar Point Cloud** 是经过检测、筛选、角度估计等处理之后得到的高层结果，只保留最终被判定为“目标”的稀疏点集。

处理流程大致为：

```text
Radar Cube / Radar Map
        ↓
CFAR Detection（检测）
        ↓
筛选出显著目标 Bin
        ↓
Angle Estimation（角度估计）
        ↓
获得 Range, Doppler, Angle, RCS
        ↓
Radar Point Cloud
```

因此 **Radar Cube 比 Radar Point Cloud 更底层，保留的信息也更多。**  
这也是为什么有些研究工作会直接使用 Radar Cube 或 Range-Doppler Map、Range-Azimuth Map —— 它们可以利用在生成点云时可能已经被丢弃的信息（例如弱目标回波）。
## 19. CFAR（恒虚警率检测）

**CFAR** 全称为 **Constant False Alarm Rate**，中文译为 **恒虚警率检测**。  
它解决的核心问题是：**雷达数据中有大量回波和噪声，到底哪些位置才是真正的目标？**

CFAR 本质上是一种 **雷达目标检测** 方法，它不依赖一个永久固定的阈值，而是根据 **待检测位置周围的局部背景能量，动态计算检测阈值**，以适应不断变化的环境。

### 为什么不能使用固定阈值？

```text
回波能量 > 固定值 → 判断为目标
```

但实际的雷达背景并不恒定：

- **空旷道路**：背景噪声较低；
- **城市道路**：墙体、护栏、其他车辆带来的大量反射，背景能量较高。

固定阈值会带来两个问题：
- **阈值太低**：噪声可能被误判为目标，导致 **虚警（False Alarm）**；
- **阈值太高**：真正的弱目标可能达不到阈值，导致 **漏检（Missed Detection）**。

因此，**当背景发生变化时，检测标准也应该动态变化。**

### CFAR 的核心思想与基本概念

CFAR 的核心是：观察待检测单元周围的背景，估计局部噪声水平，然后生成自适应阈值。

检测过程中会用到的三个重要区域：

| 单元类型           | 英文名称            | 作用                |
| :------------- | :-------------- | :---------------- |
| CUT            | Cell Under Test | 当前待判断的格子          |
| Training Cells | Training Cells  | 用于估计局部背景噪声的格子     |
| Guard Cells    | Guard Cells     | 防止目标自身能量污染噪声估计的格子 |
结构示意：

```text
Training     Guard    CUT    Guard     Training
T T T T      G G      ●      G G       T T T T
```

- **Training Cells**：用来估计背景噪声，这里的“Training”与机器学习中的“训练”不同，仅表示“利用这些单元估算背景”。
- **Guard Cells**：紧邻 CUT 的单元，不参与噪声估计，防止强目标的能量泄漏进背景估计中，导致阈值被抬高而漏掉目标。

### CFAR 的检测过程

假设通过 Training Cells 估计得到的局部背景能量为 $Noise = 10$，CFAR 算法据此计算出一个动态阈值 $Threshold = 20$。

- 如果当前待检测单元的能量 $CUT = 35$，因为 $35 > 20$，判定为可能存在目标。
- 如果 $CUT = 15$，因为 $15 < 20$，更可能只是背景噪声。

所以 CFAR 本质上就是：

> 把当前单元（CUT）的能量与一个 **局部自适应阈值** 进行比较。

### 什么是虚警（False Alarm）？

虚警是指：**实际没有目标，雷达却错误地认为有目标。** 例如，一段突然增强的噪声超过了检测阈值，就被当成目标。

CFAR 得名于其目标：**通过动态调整阈值，将虚警概率控制在一个相对稳定的水平，即“恒虚警率（Constant False Alarm Rate）”。**  
需要注意的是，这并不意味着实际虚警率永远绝对固定，而是算法设计的目标是让它受控。

==Range-Doppler Map 是 `Range × Doppler` 的二维能量图，CFAR 可以在这二维平面上逐个单元判断==：

> 在当前 Range Bin 和 Doppler Bin 位置，能量是否显著高于周围背景？

如果显著偏高，则标记为检测到目标；否则视为背景/噪声。

**直观效果对比：**

- CFAR 前：可能有大量噪声和弱回波混叠在一起；
- CFAR 后：只留下少数能量明显突出的候选目标位置。

### CFAR 与 Radar Point Cloud 的生成

当前可以形成一条从原始数据到点云的完整理解链路：

```text
Raw ADC Data
      ↓
Range FFT
      ↓
Doppler FFT
      ↓
Range-Doppler Map
      ↓
Radar Cube（多天线数据）
      ↓
CFAR Detection（检测显著目标 Bin）
      ↓
Angle Estimation（角度估计）
      ↓
获得 Range + Doppler + Angle + RCS
      ↓
Radar Point Cloud
```

### CFAR 的优缺点

**优点**：
- 检测阈值能够自适应局部背景，适合不同噪声水平、不同道路环境和不同背景回波强度。

**局限**：
- 当强弱目标靠得很近时，强目标的能量可能抬高周围 Training Cells 的噪声估计，导致临近的弱目标被漏检；
- 背景发生剧烈变化（如从空旷区域突然进入护栏/墙体密集区）时，局部噪声估计可能不准确。

因此，实际应用中存在多种 CFAR 变体（如 CA‑CFAR、OS‑CFAR、GO‑CFAR、SO‑CFAR 等），当前阶段无需深入。

## 20.Clutter（杂波）

**Clutter** 指环境中真实存在的物体产生的雷达回波，但这些物体并非我们当前关心的检测目标。

常见杂波来源包括：

- Ground / 地面
- Wall / 墙体
- Guardrail / 护栏
- Tree / 树木
- Building / 建筑物
- Road Sign / 路牌

例如雷达发射电磁波并不会只照到汽车，因此接收到的信号可能同时包含：Car Echo + Ground Echo + Wall Echo + Tree Echo + Noise。

| 类型 | 本质 |
|---|---|
| Clutter | 真实背景物体的回波 |
| Noise | 随机的电信号扰动 |

Noise 更多偏向于热噪声（Thermal Noise）、接收机噪声（Receiver Noise）、电子器件噪声（Electronic Noise）等随机摄动。

> **Clutter = 背景物体自己在反射；Noise = 随机扰动。**

若墙体、护栏、地面等相对雷达静止，则径向速度 $v_r \approx 0$，对应的多普勒频移也接近零。因此在 Range-Doppler Map 中，静态杂波常集中在 Doppler ≈ 0 附近。

为什么不能直接删除所有 Doppler ≈ 0 的点？因为真实目标也可能暂时静止，例如等红灯的汽车、停靠车辆、站立行人、暂时停止的自行车，这些目标同样可能满足 $v_r \approx 0$。因此 **Doppler ≈ 0 不等于一定是 Clutter**，简单删除所有零多普勒点会导致漏检（Missed Detection）真实目标。

## 21.Multipath（多径传播）

理想情况下雷达信号走直达路径（Direct Path）：Radar → Target → Radar。但实际环境中电磁波可能经过墙体、地面、护栏、建筑物、其他车辆等额外反射面后再返回雷达，例如 Radar → Wall → Target → Radar，这种现象即**多径传播（Multipath）**。

雷达根据传播时延估计距离。若信号绕路（如经墙体反射），传播路径变长，雷达并不知道信号经过额外反射，只能看到回波回来得更晚，于是将"路径变长"错误解释为"目标变远"，产生错误的距离估计。

假设只有一辆车，雷达可能同时收到直达路径和多条反射路径的回波。不同路径具有不同的路径长度、时延、相位和到达角，雷达可能将这些回波解释为不同的目标。于是一个真实目标可能产生：真实目标点 + 额外错误点 + 幽灵目标（Ghost Target）。

### Ghost Target（幽灵目标/假目标）

Multipath 可能产生并不存在的假目标。真实环境中只有一辆车，雷达点云中却可能出现真实目标旁边额外的多径假点，导致错误距离、错误角度和多余检测点。

### Clutter、Multipath、Noise 三者区别总结

| 类型        | 本质                 |
| --------- | ------------------ |
| Noise     | 随机电信号扰动            |
| Clutter   | 真实背景物体本身产生的回波      |
| Multipath | 电磁波经过多个传播路径产生的额外回波 |

> **Clutter = 背景物体自己在反射；Multipath = 信号绕路后又回来了；Noise = 随机扰动。**

---

## 22.Noise（噪声）

真实雷达接收到的信号可粗略表示为：Received Signal = Target Signal + Noise + Other Interference。Noise 可能来自热噪声、接收机电子器件、放大器噪声、ADC 量化噪声、外部电磁干扰等。因此雷达实际面对的不是纯净目标信号，而是目标信号叠加随机噪声。

### Noise Floor（噪声底）

Noise Floor 是系统背景噪声大致所在的能量水平。如果目标峰明显高于 Noise Floor，目标容易检测；如果目标峰接近 Noise Floor，目标容易被噪声淹没。

### SNR（Signal-to-Noise Ratio / 信噪比）

SNR 表示目标信号相对于噪声有多强：

$$SNR = \frac{P_{signal}}{P_{noise}}$$

工程中常以 dB 表示：$SNR_{dB} = 10\log_{10}(P_{signal} / P_{noise})$。

> **Signal 强、Noise 弱 → SNR 高 → 目标容易检测；**
> **Signal 弱、Noise 强 → SNR 低 → 目标容易被噪声淹没。**

为什么远距离目标容易出现低 SNR？

目标距离增加 → 传播损耗增加 → 返回雷达的目标回波变弱 → Noise Floor 不按相同比例下降 → **SNR 降低 → 更容易漏检**。因此远距离、小目标、弱反射目标通常更难检测。

### SNR 和 CFAR 的关系

- SNR 高：目标峰明显高于背景 → 容易超过 CFAR Threshold → 容易被检测。
- SNR 低：目标峰接近背景 → 可能无法超过 CFAR Threshold → 漏检（Missed Detection）。

> **SNR 是决定 CFAR 能否稳定检测目标的重要因素。**

## 23.Range Ambiguity（距离模糊）

Range Ambiguity 指回波返回得太晚，雷达无法唯一判断该回波属于哪一次发射。例如第一次发射后回波尚未返回，第二次发射已开始，晚到的回波可能和新的测量周期混淆，雷达无法判断这是上一次发射的远目标回波还是当前周期的较近目标回波。

雷达存在最大无模糊距离（Maximum Unambiguous Range），即能唯一确定目标距离而不发生周期混淆的最大范围。超过这一范围 → 回波延迟过大 → 跨越测量周期 → 可能认错发射周期 → 产生 Range Ambiguity。

---

## 24.Velocity Ambiguity（速度模糊）

多普勒测速依赖多个 Chirp 之间的相位变化。雷达通过相邻 Chirp 的相位差推断目标径向速度。

相位是周期性的（$0^\circ = 360^\circ = 720^\circ$），例如 $+240^\circ$ 和 $-120^\circ$ 在模 $360^\circ$ 意义下可能表现为同一个最终相位结果。雷达只能看到相邻两次采样间的相位差，无法判断实际变化是 $+240^\circ$ 还是 $-120^\circ$（或其他整周期叠加），因此速度无法唯一确定。

==相邻 Chirp 之间的相位变化太大，超过了相位的一个周期，而相位本身是模$360^\circ$ 的，所以雷达不知道中间到底绕了几圈。==

将相位想象成钟表指针。若每隔一段时间拍一张照片——第一张指针在 1 点，第二张在 11 点，我们无法判断指针是逆时针转了一小段还是顺时针绕了很大一圈，因为中间运动过程没有被采样。

雷达的慢时间采样类似：若目标速度过快，相位变化太快，相邻 Chirp 之间相位可能已经绕圈，雷达不知道到底转了多少圈，导致 Doppler Aliasing → Velocity Ambiguity。

| 类型                 | 核心问题                      |
| ------------------ | ------------------------- |
| Range Ambiguity    | 回波回来太晚，不知道属于哪个发射周期        |
| Velocity Ambiguity | 相位变化太快，不知道相邻 Chirp 之间绕了几圈 |

两者共同的核心思想是：**周期性 + 离散采样 → Ambiguity（模糊）**。

## 25.Window Function（窗函数）

![ChatGPT 图像 2026年9月29日 11_04_16.png](assets/P001/ChatGPT%20%E5%9B%BE%E5%83%8F%202026%E5%B9%B49%E6%9C%8829%E6%97%A5%2011_04_16.png)

FFT 实际处理的是一小段有限长度的信号。如果截取位置并非完整周期，信号两端突然断掉，这种边界突变会导致**频谱泄漏（Spectral Leakage）**。

### Spectral Leakage（频谱泄漏）

理想情况下单一频率在频谱中表现为一个尖锐的峰，但由于有限长度采样和边界突变，FFT 后主峰旁边会出现额外能量扩散。

- **频谱泄漏**：FFT 只处理有限长度的一段信号，如果截取位置不是完整周期，信号两端会突然断开，造成边界突变，于是本来集中的频率能量会“漏”到旁边频率上。
- **加窗**：让这段信号两端逐渐衰减，减少边界突变，从而减小泄漏和旁瓣。
- **加窗的代价**不是“强目标会影响弱目标”。恰恰相反，加窗通常是为了**减少强目标旁瓣对附近弱目标的遮蔽**。真正的代价是：**主瓣会变宽，分辨能力可能略有下降**。

### Window Function 的作用

![ChatGPT 图像 2026年9月29日 15_17_15.png](assets/P001/ChatGPT%20%E5%9B%BE%E5%83%8F%202026%E5%B9%B49%E6%9C%8829%E6%97%A5%2015_17_15.png)
窗函数的基本思想：**在 FFT 前让截取信号的两端逐渐减小，而不是突然截断**。原始信号的矩形截断变为平滑过渡（如 Hann 窗的两端渐变为零），从而降低边界突变，减少频谱泄漏和旁瓣（Side Lobes）。

常见窗函数包括：

- Hann Window（很常见）
- Hamming Window
- Blackman Window
- Rectangular Window

不同窗函数对主瓣宽度和旁瓣抑制能力有不同影响，现阶段无需记住具体公式，重点理解其作用即可。

Window Function 并非没有代价，通常存在**主瓣宽度（Main Lobe Width）与旁瓣抑制（Side Lobe Suppression）的权衡**：

- 不加窗 → 主峰可能更窄 → 但旁瓣较明显。
- 加窗 → 旁瓣降低 → 但主峰可能变宽。

> **加窗能减少泄漏，但可能牺牲一定的分辨能力。**

==为什么旁瓣对雷达很重要？设想两个目标：强目标（汽车）和弱目标（行人）。若强目标的旁瓣过大，弱目标可能被强目标旁瓣淹没而无法检测。窗函数可以帮助减少强目标频谱泄漏对附近弱目标的影响。==

窗函数通常应用于 FFT 之前：
- **Range FFT**：ADC Samples → Window → Range FFT
- **Doppler FFT**：Slow Time Data → Window → Doppler FFT
所以代码中看到 `Hann Window → FFT` 是雷达信号处理的常规流程。

## 1. Point Cloud 可以完成哪些感知任务？

拿到 Radar / LiDAR Point Cloud 后，可以进行多种不同任务。

常见任务包括：

```
Point Cloud
   │
   ├── Classification
   │
   ├── Semantic Segmentation
   │
   ├── Instance Segmentation
   │
   └── 3D Object Detection
```

这些任务看起来相似，但输出目标不同。

---

### 1.1 Classification（分类）

Classification 解决的问题最简单：

> **这个目标是什么？**

例如已经给模型一组汽车的点：

```
● ● ● ●
 ● ● ●
```

模型输出：

```
Car
```

它只需要判断类别，不需要告诉我们：

- 汽车具体在哪里；
    
- 汽车有多大；
    
- 汽车朝哪个方向。
    

因此 Classification 主要回答：

> **What is it?**

---

### 1.2 Semantic Segmentation（语义分割）

Semantic Segmentation 比 Classification 更细。

它不是给整个点云一个类别，而是：

> **给每一个 Point 分配一个语义类别。**

例如一帧 Radar Point Cloud 中：

```
● ● ●      → Car
● ●

        ●   → Pedestrian

● ● ●      → Background
```

模型需要判断：

```
Point 1 → Car
Point 2 → Car
Point 3 → Pedestrian
Point 4 → Background
```

因此 Semantic Segmentation 回答的是：

> **“这个点是什么？”**

---

#### Semantic Segmentation 的局限

假设场景里有两个行人：

```
● ●       ● ●
行人 A     行人 B
```

Semantic Segmentation 可能只输出：

```
Pedestrian
Pedestrian
```

它知道两个区域都属于“行人”，但不一定区分：

```
这是第 1 个行人
还是第 2 个行人
```

这就引出了 Instance Segmentation。

---

### 1.3 Instance Segmentation（实例分割）

Instance Segmentation 不仅判断类别，还要进一步区分不同个体。

例如：

```
● ●       ● ●
Person 1  Person 2
```

模型需要得到：

```
左边 → Pedestrian #1
右边 → Pedestrian #2
```

因此：

> **Semantic Segmentation = 这个点是什么？**

而：

> **Instance Segmentation = 这个点是什么，并且属于哪一个具体目标？**

---

### 1.4 3D Object Detection（三维目标检测）

对于自动驾驶来说，仅知道某些点属于 Car 或 Pedestrian 往往还不够。

系统还需要知道：

- 目标在哪里；
    
- 距离多远；
    
- 目标有多大；
    
- 目标朝哪个方向。
    

因此需要进行：

> **3D Object Detection（三维目标检测）**

它的核心任务可以概括为：

```
Point Cloud
      ↓
找出目标
      ↓
判断类别
      ↓
估计目标三维位置
      ↓
估计目标长宽高
      ↓
估计目标朝向
      ↓
3D Bounding Box
```

例如：

```
Car
中心位置：
x = 20.1 m
y = 2.3 m
z = 0.8 m

尺寸：
length = 4.2 m
width  = 1.8 m
height = 1.6 m

朝向：
yaw = 15°
```

最终可以在三维空间中给汽车套上一个长方体。

---

## 2. 3D Bounding Box（三维边界框）

### 2.1 从 2D Bounding Box 到 3D Bounding Box

在 Camera 图像中，目标检测通常输出二维矩形框：

```
Image

+------------------------+
|                        |
|      ┌────────┐        |
|      │  Car   │        |
|      └────────┘        |
|                        |
+------------------------+
```

一个 2D Bounding Box 通常描述：

```
x
y
width
height
```

也就是：

> 目标在图片中的位置和大小。

而 LiDAR / Radar 感知的是三维真实空间，因此需要：

> **3D Bounding Box**

可以把它理解成：

```
2D Bounding Box
→ 图片上套矩形

3D Bounding Box
→ 三维空间里套长方体
```

---

### 2.2 一个 3D Bounding Box 通常包含什么？

典型参数包括：

- **x, y, z**：目标中心位置；
    
- **length**：长度；
    
- **width**：宽度；
    
- **height**：高度；
    
- **yaw**：水平面上的朝向角。
    

即：

```
位置
+
尺寸
+
方向
```

因此：

> **3D Object Detection 的核心输出之一就是 3D Bounding Box。**

---

### 2.2.1 参数速查与使用约定

$$
\mathbf b=(x,y,z,l,w,h,\theta)
$$

这里 $\theta$ 通常就是 Yaw。不同数据集对框中心、长宽对应的轴和朝向角零点可能采用不同约定，使用标签前必须确认。

> **与 RadarVisionLLM 的关系**：P001 的分类分支回答类别，框回归分支估计这七个参数；少量 Radar 散射点的外接框不能直接当作整车真实框。

---

### 2.3 为什么 Elevation 对 3D Object Detection 很重要？

传统 2+1D Radar 主要能够获得：

```
Range
Azimuth
Doppler
```

可以较好回答：

```
目标有多远？
目标在左边还是右边？
目标沿 LOS 怎么运动？
```

但是缺乏可靠的：

```
Elevation
```

因此难以准确获得：

- 目标在多高的位置；
    
- Point 的 z 坐标；
    
- 目标本身高度；
    
- 3D Bounding Box 在垂直方向上的位置。
    

例如从俯视角度：

```
Radar ● -------- ●
```

两个点可能看起来位置相近。

但从侧面看：

```
        ●  ← 车身

Radar ●

        ●  ← 地面
```

如果没有 Elevation，就很难区分它们的高度。

因此：

> **Elevation 是 Radar 从平面感知走向完整 3D 感知的重要信息。**

---

### 2.4 6-DoF（Six Degrees of Freedom，六自由度）

**DoF（Degrees of Freedom）表示自由度。** 在三维空间中，刚体的 **6-DoF Pose（六自由度位姿）** 通常指 3 个平移自由度和 3 个旋转自由度。

- **Translation（平移）**：x、y、z，描述位置；
- **Rotation（旋转）**：Roll（横滚）、Pitch（俯仰）、Yaw（偏航），描述姿态。常见约定分别对应绕 x、y、z 轴旋转，但具体轴定义须查看坐标系约定。

```text
6-DoF Pose（刚体位姿）
├── Translation：x、y、z
└── Rotation：Roll、Pitch、Yaw
```

### 6-DoF 与 3D Bounding Box 不是一回事

前面提到的常见汽车检测框表示为 `x, y, z, length, width, height, yaw`，共 **7 个参数**：3 个位置、3 个尺寸、1 个偏航角。它假设目标主要在水平面上朝向变化。

而**刚体 6-DoF Pose** 不包含长宽高；如果一个 3D Box 同时编码位置、三维尺寸和完整三轴姿态，则通常涉及 **9 个参数**。所以 **自由度数量不等于框参数总数**。

> **位置回答“在哪里”，姿态回答“怎么转”，尺寸回答“有多大”。**

## 3. Bounding Box Regression（边界框回归）

3D Object Detection 不只是分类问题。

模型不仅需要判断：

```
Car / Pedestrian / Cyclist
```

还要预测：

```
x
y
z
length
width
height
yaw
```

这些值都是连续数值，因此属于：

> **Regression（回归）问题**

所以：

> **Bounding Box Regression = 预测目标边界框的位置、尺寸和方向等连续参数。**

---

### 为什么 Radar 做 Bounding Box Regression 比较困难？

假设 LiDAR 在一辆汽车上产生大量点：

```
● ● ● ● ● ●
● ● ● ● ● ●
● ● ● ● ● ●
```

那么模型比较容易观察车辆轮廓。

而 Radar 可能只有：

```
●             ●

       ●
```

模型需要根据很少的散射点去估计整辆汽车的：

- 长度；
    
- 宽度；
    
- 高度；
    
- 方向。
    

因此：

> **Radar Point Cloud 的稀疏性是 Radar 3D Bounding Box Regression 的核心困难之一。**

---

### Classification、Segmentation 与 3D Detection 的区别

这一组概念以后会频繁出现，需要区分清楚。

| 任务                    | 核心问题          | 主要输出                 |
| --------------------- | ------------- | -------------------- |
| Classification        | 这是什么？         | 类别                   |
| Semantic Segmentation | 每个点是什么？       | 每个点的类别               |
| Instance Segmentation | 每个点属于哪个具体目标？  | 类别 + 实例              |
| 3D Object Detection   | 目标在哪里、有多大、朝哪？ | 类别 + 3D Bounding Box |

例如同一辆汽车：

Classification

```
这一团点
↓
Car
```

Semantic Segmentation

```
这些点
↓
全部标记为 Car
```

Instance Segmentation

```
这些点
↓
Car #1
```

3D Object Detection

```
这些点
↓
Car
+
位置
+
长宽高
+
方向
↓
完整 3D Bounding Box
```

> **Multi-Class 3D Object Detection**

而不仅仅是 Point Classification 或 Segmentation。

---

## 4. BEV（Bird's-Eye View，鸟瞰图）

进入 3D Object Detection 后，会经常看到一个非常重要的表示：

> **BEV（Bird's-Eye View，鸟瞰图）**

BEV 就是：

> **从正上方向下看场景。**

例如真实道路：

```
Camera View

        Car
         🚗

---------------- Road
```

转换成 BEV：

```
Top View

        ┌────┐
        │Car │
        └────┘

---------------- Road
```

---

### 为什么自动驾驶很喜欢 BEV？

因为车辆主要在地面上运动。

从 BEV 看：

- 前后距离清楚；
    
- 左右位置清楚；
    
- 车辆之间空间关系清楚；
    
- 目标方向容易表示；
    
- 很适合预测 3D Bounding Box。
    

因此很多 LiDAR、Radar、Camera 3D Detection 方法都会把==特征转换到==：

> **BEV Space**

---

### 从空间点到网络输入：Point / Voxel / Pillar

前面确定了检测输出，接下来要选择输入表示。相同点云可以保留为不规则点集合，也可以先按空间区域聚合。

| 表示 | 基本单元 | 主要取舍 |
|---|---|---|
| Point-based | 单个点 $(x,y,z,v_r,\mathrm{RCS})$ | 保留点级信息；点数和邻域不规则 |
| Voxel-based | 三维小立方体 | 保留三维局部结构；网格越细，资源开销越大 |
| Pillar-based | XY 网格向高度方向延伸的柱体 | 便于二维 BEV 计算；高度信息需要编码进特征通道 |

这里 $v_r$ 是径向速度，不是完整三维速度向量。Voxel 同时离散 x、y、z；Pillar 只在 x、y 上划格，但可以用点的 z 坐标编码高度信息。

```text
Radar Points
├── 不划网格 → Point-based
├── XYZ 划格 → Voxel-based
└── XY 划格  → Pillar-based → BEV Feature
```

> **与 RadarVisionLLM 的关系**：P001 采用的 PointPillars 属于第三类。下面先解释 Pillar，再解释它怎样生成检测所需的 BEV 特征。

---

## 5. Pillar（柱体）

理解 PointPillars 之前，需要先理解 Pillar。

在 BEV 的 x-y 平面上，可以把整个空间划分成很多小格子：

```
BEV

┌──┬──┬──┬──┐
│  │● │  │  │
├──┼──┼──┼──┤
│● │● │  │  │
├──┼──┼──┼──┤
│  │  │● │  │
└──┴──┴──┴──┘
```

每一个小格子在垂直 z 方向向上延伸，就形成一个：

> **Pillar**

可以把它想象成：

```
       │     │
       │ ●   │
       │   ● │
       │     │
       │ ●   │
       └─────┘
         Pillar
```

因此 Pillar 本质上是：

> **x-y 平面上的一个小区域 + 整个垂直方向。**

落入同一个 Pillar 中的 Points 会被一起编码成一个特征。

### PointPillars 初步认识

PointPillars 是经典的：

> **Point Cloud 3D Object Detection 方法**

最初主要用于 LiDAR Point Cloud。

它的核心思想可以暂时理解为：

```
Point Cloud
     ↓
划分 Pillars
     ↓
提取每个 Pillar 内 Points 的特征
     ↓
生成 BEV Feature Map
     ↓
2D CNN
     ↓
Detection Head
     ↓
3D Bounding Boxes
```

---

原始 Point Cloud 是不规则的：

```
       ●

 ●          ●

          ●
```

普通 CNN 更擅长处理规则网格，例如图像：

```
[ ][ ][ ][ ]
[ ][ ][ ][ ]
[ ][ ][ ][ ]
```

PointPillars 的核心作用之一，就是：

> **把不规则 Point Cloud 转换为规则的 BEV Feature Map。**

这样就可以利用成熟的 2D CNN 做后续检测。

---

### 从 Pillar 到检测框：各模块负责什么？

1. **Pillarization**：按点的 XY 位置分组，确定点属于哪根柱体。
2. **Pillar Feature Encoder**：对点属性及相对柱体中心、点簇中心的位置进行编码，再聚合成固定长度的柱体特征。
3. **Scatter**：把非空柱体的特征放回对应的 BEV 网格。
4. **2D Backbone**：使用二维卷积融合相邻区域的上下文。
5. **Detection Head**：输出类别分数与边界框参数。

```text
每柱若干点 → 共享点特征变换 → 聚合 → 一根柱体的特征向量
                                          ↓ Scatter
                                    BEV → Backbone → Head
```

这能把不规则输入转换为规则计算，同时保留 Doppler、RCS 等物理属性。Pillar 网格也带来空间量化，编码器需要在特征中保留格内细节。

P001 使用成熟的 PointPillars 作为基线，便于在相对一致的检测框架下比较 Radar 特征和多帧累积的贡献。这个选择不意味着 PointPillars 天然解决了雷达稀疏性。

> **与 RadarVisionLLM 的关系**：阅读检测器时，先定位输入、Encoder、Backbone、Head，再判断论文修改发生在哪里；它们的功能不同。

## 6. Data Augmentation（数据增强）

深度学习训练通常需要大量数据。

但真实数据有限，因此可以对已有数据进行合理变换：

```
原始训练数据
      ↓
旋转 / 平移 / 翻转 / 缩放
      ↓
产生更多不同训练样本
      ↓
提高训练数据多样性
```

这种方法称为：

> **Data Augmentation（数据增强）**

常见操作包括：

- Rotation；
    
- Translation；
    
- Scaling；
    
- Flipping；
    
- Sampling。
    

---

### 为什么 LiDAR 的 Data Augmentation 不能直接照搬到 Radar？

LiDAR Point 主要包含几何信息，例如：

```
x, y, z, intensity
```

而 Radar Point 还可能包含：

```
Doppler
RCS
```

例如把一个 Radar Point Cloud 旋转：

```
原来的目标方向
        ↓
进行 Rotation
        ↓
目标相对于 Radar 的方向改变
```

但 Doppler 表示的是：

> **目标沿 Radar LOS 方向的径向速度。**

如果只变换点的位置而没有同步处理速度向量、雷达视线和传感器坐标关系，那么：

```
空间位置
和
物理速度属性
```

可能不再一致。

因此：

> **Radar Data Augmentation 必须考虑 Radar 物理属性，不能机械照搬 LiDAR Augmentation。**

这是 Radar 与 LiDAR 在深度学习处理中非常重要的差异。

---

## 7. Coordinate System & Transformation（坐标系与坐标变换）

### 7.1 为什么需要坐标系？

Radar、Camera 和 LiDAR 安装在车辆的不同位置，测量结果通常以各自传感器为原点表示，同一个真实点在三个传感器中的坐标可能不同：

```text
同一个 Car
├── Radar 坐标系：(xr, yr, zr)
├── LiDAR 坐标系：(xl, yl, zl)
└── Camera 坐标系：(xc, yc, zc)
```

坐标值不同，不代表三个传感器看到的是三个物体——它们只是使用了不同的参考原点和轴方向。要进行融合，必须明确各坐标系的原点、x/y/z 轴方向和单位。

### 7.2 Coordinate Transformation（坐标变换）

坐标变换就是把某个坐标系中的点，换算为另一个坐标系下的表示。对于刚体坐标系，常用旋转矩阵 $R$ 和平移向量 $t$：

$$
\mathbf p_B = \mathbf R_{B\leftarrow A}\mathbf p_A + \mathbf t_{B\leftarrow A}
$$

- $\mathbf p_A$：点在 A 坐标系中的坐标
- $\mathbf R$：描述 A 到 B 的轴方向差异
- $\mathbf t$：描述两个坐标系原点的相对位置
- $\mathbf p_B$：点在 B 坐标系中的坐标

**直觉：先把方向转对，再把位置移对。**

```text
Radar Point (Radar坐标系)
             ↓
    Rotation + Translation
             ↓
同一 Point (Camera坐标系)
```

如果使用齐次坐标，也可以写为一个 $4\times4$ 变换矩阵：

$$
\begin{bmatrix}\mathbf p_B\\1\end{bmatrix}
=
\underbrace{\begin{bmatrix}\mathbf R&\mathbf t\\0&1\end{bmatrix}}_{\mathbf T_{B\leftarrow A}}
\begin{bmatrix}\mathbf p_A\\1\end{bmatrix}
$$

注意：把三维点变到 Camera 坐标系后，还需利用相机内参进行透视投影，才能得到图像上的像素坐标 $(u, v)$。

## 8. Calibration（传感器标定）

Calibration 是确定传感器测量模型或不同传感器之间几何关系的过程。

### 8.1 Extrinsic Calibration（外参标定）

外参描述两个坐标系之间的相对旋转和平移，即前面的 $\mathbf R$ 和 $\mathbf t$。例如将 Radar 点投影到 Camera 图像：

```text
Radar Point
    ↓  Radar→Camera Extrinsics
Camera坐标系下的3D Point
    ↓  Camera Intrinsics / Projection
Camera Image中的像素位置
```

> Extrinsic Calibration 主要解决"不同传感器的空间坐标如何对应"。

### 8.2 Intrinsic Calibration（内参标定）

相机内参包括焦距、主点等与成像几何有关的参数；镜头畸变也需要通过标定模型处理。内参帮助把相机坐标系中的三维点映射到图像像素。

```text
Extrinsics（外参）→ 不同坐标系之间如何变换
Intrinsics（内参）→ 相机如何把三维位置映射成像素
```

> 空间标定准确，并不保证不同传感器记录的是同一时刻；这还需要 Synchronization。

---

### 8.3 Radar 点怎样投影到图像？

将前面的外参变换和相机成像连接起来：

$$
\mathbf P_{camera}=R\mathbf P_{radar}+t
$$

$$
s\begin{bmatrix}u\\v\\1\end{bmatrix}
=K\begin{bmatrix}X_c\\Y_c\\Z_c\end{bmatrix},
\qquad
K=\begin{bmatrix}f_x&0&c_x\\0&f_y&c_y\\0&0&1\end{bmatrix}
$$

这里 $s=Z_c$（采用相机 Z 轴朝前的约定），$(f_x,f_y)$ 为像素单位的焦距，$(c_x,c_y)$ 为主点。直观上就是先变换坐标，再除以深度，最后换算成像素。公式假设图像已去畸变或采用理想针孔模型。

```text
Radar 3D 点 → R、t → Camera 3D 点 → K、透视除法 → Pixel
```

点必须在相机前方且投影位于图像范围内；几何投影落在某个物体像素上，也不自动保证二者属于同一物体，还需要考虑遮挡、测量误差与时间差。

> **与 RadarVisionLLM 的关系**：标定建立空间对应，同步建立时间对应，两者共同支持后续雷视融合。

## 9. Synchronization（时间同步）

Camera、Radar、LiDAR、Odometry 具有不同采样频率，同一场景的数据不一定在同一时刻获得：

```text
Camera：t = 1.00 s
Radar ：t = 1.04 s
LiDAR ：t = 1.02 s
```

如果汽车正在运动，即使空间标定正确，不同时刻的目标也可能已经发生位置变化，造成投影偏差或融合错误。

Synchronization 就是建立跨传感器数据在时间上的对应关系，可以依据时间戳选取最近测量，也可以在条件允许时进行插值、运动补偿等处理。

VoD 使用 LiDAR 时间戳作为同步参考，寻找对应的 Radar、Camera、Odometry 数据并组成约 10 Hz 的同步帧（其他数据集可能采用不同策略）。

```text
Calibration    → Spatial Alignment（空间对齐）
Synchronization→ Temporal Alignment（时间对齐）
```

---

## 10. Frame / Sequence / Clip（帧、序列与片段）

### 10.1 Frame（帧）

一帧是某个参考时间点附近的一次数据记录。在多传感器数据集中，一帧可以包含匹配的 Camera 图像、Radar 点云、LiDAR 点云、时间戳及位姿等。

注意：同步帧不一定代表所有传感器在完全相同的瞬间曝光或扫描，它通常是按时间戳匹配的一组观测。

### 10.2 Sequence（序列）与 Clip（片段）

- **Sequence**：按时间先后排列的多帧数据
- **Clip**：从连续数据中截取的一段，通常有明确的起止时间

```text
Frame t → Frame t+1 → Frame t+2 → ...
                  \____________/
                       Clip
```

有连续帧才能分析目标运动、执行跟踪、估计轨迹或累积多帧点云。如果数据集中还提供跨帧 Object ID，就更容易关联不同帧中的同一目标。

---

## 11. Odometry（里程计）

Odometry 用于估计自车（Ego Vehicle）随时间的运动，常表现为相邻时刻的位姿变化。

在车载系统中可以融合 Wheel Odometry、IMU（角速度、加速度）、GPS / RTK GPS 等数据，通过滤波或优化算法得到更稳定的车辆运动估计。

```text
t1：自车位于位置 A，朝向 α
          ↓  Odometry
t2：自车位于位置 B，朝向 β
```

Odometry 描述的是传感器所在车辆怎么移动，并不直接给出前方行人或其他汽车的真实运动轨迹。它与定位（Localization）相关但不完全等同于绝对定位；纯里程计也可能存在累计漂移。

---
## 12. Ego-motion Compensation（自车运动补偿）

### 12.1 为什么需要补偿？

Radar 安装在行驶的车辆上。即使路边的路灯或墙体静止，它们在车载 Radar 坐标系里的位置也会随着车辆移动而改变：

```text
真实世界：Pole 不动，Ego Car 向前移动
传感器视角：Pole 的相对位置一直变化
```

若把不同时间的 Radar points 直接叠加，同一个静止物体可能出现多处点迹。

### 12.2 怎么补偿？

通过 Odometry / Ego Pose 得到不同帧之间的坐标变换，再把历史点云统一变换到某个参考帧（通常是当前帧）：

$$
\mathbf p_{\mathrm{current}}=
\mathbf T_{\mathrm{current}\leftarrow\mathrm{past}}
\mathbf p_{\mathrm{past}}
$$

```text
过去帧 Radar Points
       ↓
自车位姿 / 坐标变换
       ↓
统一到当前帧坐标系
       ↓
尽量对齐静态环境
```

### 12.3 与目标运动补偿的区别

Ego-motion Compensation 只消除由自车运动造成的坐标变化；如果前方自行车本身在运动，多帧中它依然可能位于不同位置。

```text
Ego-motion：自车在动 → 需要转换坐标系
Object motion：目标在动 → 还可能需要目标级运动建模
```

另外需区分两种处理：点云位置补偿和径向速度的自车运动修正是不同的运算，后者需要考虑自车速度在每条雷达视线方向上的投影。

## 13. Temporal Accumulation（时间累积 / 多帧累积）

前面已经知道：

> Radar Point Cloud 通常比较稀疏。

假设单帧只有：

```
Frame t

   ●

        ●

 ●
```

如果连续采集多帧：

```
Frame t-2
Frame t-1
Frame t
```

并将它们对齐后叠加：

```
Frame t-2
     +
Frame t-1
     +
Frame t
     ↓

●   ●
  ● ●
●   ●   ●
   ●
```

点数就会增加。

这种方法称为：

> **Temporal Accumulation / Multi-frame Accumulation**

---

### 为什么要进行 Temporal Accumulation？

核心目的：

```
单帧 Radar Point Cloud 稀疏
            ↓
累积连续多个 Radar Frames
            ↓
获得更多 Radar Points
            ↓
目标结构更加完整
            ↓
提高 Detection 能力
```

因此 Temporal Accumulation 是解决：

> **Radar Sparsity**

的一种常见方法。

---

### Temporal Accumulation 也有问题

如果目标是运动的：

```
t-2       ●

t-1          ●

t               ●
```

直接叠加后：

```
●  ●  ●
```

同一个目标可能被拉成一串。

这种现象可以理解为：

> **Motion Smearing / 运动拖影**

结合前面介绍的 Odometry 和 Ego-motion Compensation，真正进行多帧累积时还要考虑：

- Ego-motion Compensation；
    
- Object Motion；
    
- Coordinate Transformation；
    
- 不同帧之间的时间差。

---

### 时间累积与 Temporal Fusion 的关系

Temporal Accumulation 是在输入点云层叠加历史观测；更广义的 Temporal Fusion 也可以在特征层或预测层融合历史信息。两者不能直接画等号。

```text
点级累积：历史点 → 坐标对齐 → 合并当前点云 → 编码
特征融合：历史帧 → 分别编码 → 对齐特征 → 时序融合
```

除了运动拖影，还可能出现 Ghosting：错误对齐或保留过时观测，造成重复位置或假目标。它与第一部分由多径产生的 Ghost Target 现象相似，但来源不同。

更长时间窗增加点数，也增加运动变化与时延。P001 比较不同 scans 的累积效果，阅读时要同时检查帧数、补偿方式和参考时刻。

> **与 RadarVisionLLM 的关系**：未来序列 Token 需要保留 timestamp；只有坐标而没有时间，模型无法分辨当前点与历史点。

## 14. 完整知识链

### Radar Perception Pipeline（雷达感知完整流程）

把 Radar Signal Processing 和 3D Perception 串成一条链路：

```text
Radar Echo → Beat Signal → ADC Sampling → Window
→ Range FFT → Doppler FFT → Radar Cube / Radar Maps
→ CFAR → Angle Estimation → Radar Point Cloud
─────────────────────────────────────────────
           从信号处理进入感知算法
─────────────────────────────────────────────
→ Point Cloud Processing → Pillarization
→ BEV Feature → PointPillars / 3D Detector
→ Classification + Bounding Box Regression
→ 3D Bounding Box → Car / Pedestrian / Cyclist Detection
```

Radar Cube 是多维数据的组织方式，而不是必须位于 Angle Estimation 之后的单独运算。常见实现先在 Range–Doppler 域做 CFAR，再对候选单元估角；也有实现先形成角度谱，再检测。上面的流程展示一种常见处理顺序，具体以传感器输出和论文实现为准。

信号处理阶段回答“哪里存在可测回波、它的距离与径向速度是多少”；深度学习阶段进一步回答“这些点属于什么目标，完整目标框在哪里”。CFAR 的检测点不等于语义目标，一个目标可以对应多个点。前级被过滤掉的信息，后级通常无法直接恢复。

> **与 RadarVisionLLM 的关系**：P001 从点云开始；后续选择 Radar Cube、BEV 或 Token 作为输入，表示在这条链路上选择不同的信息接口。


感知阶段需重点关注的两个问题：

- **Radar Point Cloud 稀疏** → Temporal Accumulation
- **Radar Point 具有 Doppler / RCS** → 需要 Radar-aware Data Augmentation

## 15. Detection Evaluation Metrics

检测指标不仅判断类别是否正确，还要判断预测框与真实框是否足够重合。

### IoU（Intersection over Union）

$$
\mathrm{IoU}=\frac{|B_{pred}\cap B_{gt}|}{|B_{pred}\cup B_{gt}|}
$$

IoU 越大，预测框与真实框重合越好。3D 检测论文可能使用 BEV IoU 或 3D IoU，阅读表格前必须先确认评估空间和匹配阈值。

### Precision 与 Recall

$$
\mathrm{Precision}=\frac{TP}{TP+FP}
$$

$$
\mathrm{Recall}=\frac{TP}{TP+FN}
$$

TP 是正确匹配的预测，FP 是未正确匹配的预测，FN 是未被匹配的真实目标。通常同一个真实目标只允许匹配一个预测，多余重复框会计为 FP；匹配还要求类别正确。

Precision 关注“报出的目标有多少是真的”，Recall 关注“真实目标有多少被找到”。改变置信度阈值通常会让二者此消彼长。

### AP 与 mAP

PR Curve 的横轴是 Recall，纵轴是 Precision。AP 的具体插值、采样点和汇总规则依赖评估协议，不能把不同协议的 AP 当成同一指标。

AP（Average Precision）概括一个类别在不同置信度阈值下的 Precision-Recall 表现；mAP（mean AP）再对多个类别或多个规定条件下的 AP 求平均。

```text
Prediction + Ground Truth
          ↓ IoU 匹配
       TP / FP / FN
          ↓ 扫描置信度阈值
 Precision-Recall Curve
          ↓ 面积汇总
            AP
          ↓ 跨类别平均
           mAP
```

结合仓库中 P001 的实验笔记，可以这样读取指标：

- **评价约定**：使用 3D IoU，Car 阈值为 0.5，Pedestrian 和 Cyclist 为 0.25；mAP 对三类 AP 求平均。不同区域和不同阈值的分数不能直接混用。
- **Table IV**：先确认比较设置，再看类别 AP 和 mAP。例如整个标注区域的单帧 Radar mAP 为 38.0，三帧为 46.3，五帧为 47.0；增加帧数的收益并不线性。
- **Fig. 5**：观察 IoU 阈值提高后性能如何变化。Radar 表现随严格定位要求更早下降，说明“发现目标”与“框得精确”是不同能力。

这些数值只用于演示读表方法，详细实验设置集中保留在 [P001 论文笔记](P001_%E8%AE%BA%E6%96%87%E7%B2%BE%E8%AF%BB.md)，避免在概念笔记中重复维护整张结果表。

> **与 RadarVisionLLM 的关系**：统一指标定义后，才能公平比较 Radar-only、Camera-only 与 Fusion 模型，也才能判断某种 Token 表示改善的是分类、召回还是空间定位。

# 三、Radar-Camera Fusion（雷视融合基础）

## 1. 融合什么，以及在哪里融合

Camera 提供丰富的纹理、颜色和语义，Radar 提供较稳定的距离与径向速度。融合的关键问题是：在网络的哪个阶段让两种信息交互？

### Early Fusion

在输入或非常浅的特征阶段融合，例如把投影到图像的 Radar 点属性附加为额外通道。

```text
Radar Raw/Input + Camera Input → Shared Network
```

它能较早建立跨模态联系，但对空间对齐、时间同步和输入密度差异较敏感。

### Middle Fusion

先分别提取模态特征，再在图像、BEV 或多尺度特征层进行交互。

```text
Radar → Radar Encoder ─┐
                       ├→ Feature Fusion → Detection
Camera → Image Encoder ┘
```

Middle Fusion 保留了各自专用的编码器，又允许网络在形成最终预测前学习互补关系。它能在多个尺度或位置上进行融合，比简单拼接输入更灵活，也比只合并结果包含更多细粒度信息，因此它是 Radar-Camera 检测中常见的设计选择。实际效果仍依赖对齐质量、训练数据和计算预算。

### Late Fusion

两个分支先独立输出检测结果，再进行框匹配、置信度合并或决策选择。

```text
Radar → Detection ─┐
                    ├→ Decision Fusion
Camera → Detection ┘
```

它模块化程度高，对单个传感器分支改动较小，但跨模态交互发生较晚，难以利用目标内部的局部互补信息。

> **与 RadarVisionLLM 的关系**：阅读 相关雷视融合工作 时，先定位 Radar 与 Camera 各自的编码空间，再寻找融合发生的位置、方向和尺度；这比先记模块名称更重要。

---

## 2. 在 BEV 中建立跨模态对应

第二部分第 4 节解释了 BEV 的几何意义。这里继续回答：不同模态怎样形成可融合的空间特征？

```text
Camera Image：透视二维平面 (u, v)
                         ↘
                          统一 BEV：道路平面 (x, y)
                         ↗
Radar Points：三维坐标 (x, y, z)
```

Radar 点本身带有三维位置，可以按 $(x,y)$ 直接落入 BEV 网格。Camera 图像则必须借助相机标定、深度估计或视角变换，把图像特征提升并映射到空间坐标。完成映射后，两类特征才可以按空间位置对齐和融合。

> **与 RadarVisionLLM 的关系**：BEV 是 P001 的检测空间，也是 Radar-Camera Middle Fusion 常见的共享表示空间，为阅读 相关雷视融合工作 建立了坐标基础。

标定只能提供相机像素对应的空间射线，单张图像的一个像素本身不能唯一确定三维深度。因此 Camera 到 BEV 还需要深度信息、几何假设或可学习的映射，不能仅凭内参和外参直接完成。

### 阅读融合模块的顺序

```text
空间标定 + 时间同步（第二部分 7–9 节）
                     ↓
各模态编码 → 确认坐标空间 → 建立对应 → 特征交互 → 检测输出
```

阅读 后续雷视融合论文 时，沿这条顺序定位论文模块，具体结构以原文为准。理解其对齐方式后，再去看 Attention 如何选择来自另一模态的信息。

# 四、Token、Attention 与 Transformer 基础

## 1. Token Representation for Sensor Data（传感器数据的 Token 表示）

神经网络中的 Token 是模型处理和交换信息的基本单元。Transformer 通常接收一组固定特征维度的向量。连续传感器数据需要先选择处理单元，再把每个单元编码成向量；这一步称为 Tokenization。它不要求把连续数值量化成离散词表，也不是所有传感器网络都必须使用 Token。

```text
Text：          Word / Subword         → Token
Time Series：   Signal Patch           → Token
Radar：         Point / Pillar / Frame → Token
```

一种点级 Radar Token 可以包含：

$$
\mathbf r_i=(x_i,y_i,z_i,v_i,\mathrm{RCS}_i,t_i)
$$

再通过可学习的编码器映射到统一维度。这里的 $t_i$ 是 timestamp，用于说明观测发生的时间。实际 Token 还需要位置编码、有效性标记或传感器标识，才能让模型区分空间、时间与模态来源。

Radar Token 的粒度可以不同：

- **Point Token**：细粒度高，但 Token 数量随点数变化，且单点语义弱；
- **Pillar / Voxel Token**：先聚合局部区域，结构规则且适合与 BEV 对齐；
- **Frame Token**：表示整帧全局状态，序列较短，但可能丢失局部目标细节。

Token 化不是简单改名，而是一次信息取舍：聚合越强，计算通常越省，但被压缩的细节越难恢复。

> **与 RadarVisionLLM 的关系**：Radar Token 是把信号处理与 Foundation Model 接起来的接口。未来研究需要明确 Token 来自 Raw ADC、Radar Cube、Point、Pillar 还是 Frame，以及它保留了哪些物理量。

### Token 与 Embedding 的区别

Token 是“选取什么作为一个单元”，Embedding 是“把该单元编码成什么向量”。例如一个 Radar Point 是原始单元，经线性层或小型网络编码后，可以得到一个 $d$ 维向量；加入位置、时间信息后，再参与后续交互。

```text
Point / Pillar / Patch → Encoder → d 维 Embedding
                                      + 位置与时间编码
                                               ↓
                                         Transformer 输入
```

因此，先明确 Token 的物理含义，再学习 Attention 如何在 Token 之间传递信息。

---

## 2. Attention（注意力机制）

Attention 的核心思想是：对当前要更新的信息，动态判断其他信息的重要程度，再按权重聚合。

```text
当前查询内容 Q
      ↓ 与 K 比较相关性
一组注意力权重
      ↓ 对 V 加权求和
新的上下文表示
```

常用形式为：

$$
\mathrm{Attention}(Q,K,V)
=\mathrm{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

- **Query（Q）**：当前在寻找什么；
- **Key（K）**：每个信息单元提供什么匹配线索；
- **Value（V）**：匹配后真正被聚合的内容。

这里 $d_k$ 是 Key 的特征维度，softmax 对每个 Query 对应的一组相关性分数归一化，使其成为加权系数。Q、K、V 通常由输入特征经过可学习线性变换得到。

### Self-Attention 与 Cross-Attention

- **Self-Attention**：Q、K、V 来自同一组输入，例如同一帧 Radar Tokens 之间交互。
- **Cross-Attention**：Q 来自一组输入，K、V 来自另一组，例如 Radar 查询 Camera 特征。

```text
Self： Radar Q → Radar K、V → 更新 Radar
Cross：Radar Q → Camera K、V → 更新 Radar
```

## 3. Transformer（基于注意力的网络）

典型 Transformer 模块由 Attention、前馈网络（FFN）、残差连接和归一化组成。Attention 负责单元之间交换信息，FFN 进一步变换每个单元的特征；多层叠加逐步形成上下文表示。

```text
Tokens → Attention + 残差/归一化 → FFN + 残差/归一化
                         ↓ 多层重复
                  Contextual Features
```

Transformer 通过多层 Attention 和特征变换，让不同 Token 交换上下文。它适合处理点、帧或模态之间并非固定局部邻接的关系，但 Attention 本身并不会自动理解距离、时间或传感器坐标，这些信息仍需通过特征或位置编码提供。

> **与 RadarVisionLLM 的关系**：Radar 点可以关注同一目标的其他点，当前帧可以关注历史帧，Radar Token 也可以关注 Camera Token；Attention 提供的是统一的信息交互机制。

## 4. Foundation Model（基础模型）

Foundation Model 通常指在较广泛数据和任务上预训练、能够适配多种下游任务的模型。Transformer 是一种网络架构，Foundation Model 描述训练规模、覆盖范围与迁移能力；使用 Transformer 并不自动成为基础模型。

```text
传感器表示 → Tokens → 大范围预训练 → 可迁移特征 → 下游任务适配
```

> **与 RadarVisionLLM 的关系**：当前先建立可解释的 Radar 表示与可靠评估基础，再理解预训练、迁移和多模态对齐需要哪些数据与任务。Radar Token 也不等于文本 Token，统一向量维度不代表已经完成语义对齐。

# 五、Robust Radar Perception（鲁棒雷达感知）

Robust Radar Perception 关注模型在非理想条件下是否仍能可靠工作。本节只界定问题，不提前给出解决方案。

## 1. Sparse Radar（稀疏观测）

目标只有少量回波，点数还会随距离、材质和视角变化。小目标可能在某些帧中完全没有稳定检测点。

## 2. Long Range Detection（远距离检测）

距离增加后，回波通常更弱、角度误差对应的横向位置误差更大，目标之间也更容易在有限分辨率下混合。

## 3. Missing Modality（模态缺失）

Radar-Camera 系统可能遇到相机过曝、遮挡、通信中断或某个传感器暂时不可用。训练时默认模态始终齐全，会让实际部署产生分布差异。

## 4. Noise（观测干扰）

噪声、杂波、多径与虚警会形成不稳定观测。它们不仅影响点云，也会沿感知流水线传播到特征和最终检测结果。

## 5. Domain Shift（域偏移）

训练与测试环境可能在城市、道路结构、天气、传感器型号、安装位置或标注规则上不同。模型学到的数据规律不一定能直接迁移到新域。

```text
理想训练数据
     ↓ 遇到稀疏、远距、缺失、噪声、域变化
真实部署数据
     ↓
性能与可靠性可能下降
```

> **与 RadarVisionLLM 的关系**：这些问题决定未来模型是否只在单一数据集上有效。建立 Foundation Model 之前，需要先能清楚描述模型面对的输入缺陷和泛化边界。
