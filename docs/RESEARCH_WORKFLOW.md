# 长期科研协作与证据交付

本文件执行用户已明确的角色/两遍阅读原则，不替代《第四次学习规划》。当前仓库未定位该规划原文，保留缺口；收到原文后建立引用，不凭摘要删减或推测它的具体步骤。

## 分工

- ChatGPT作为科研教师：概念讲解、论文理解题批改、证据审阅及阶段验收。
- 用户作为学习者：亲自理解与回答开放题，核对研究判断并决定方向。
- Codex作为工程执行者：执行已授权文件/代码工作、证据留存、日志、图表、检查与Git同步；不代填学习者回答或教师历史批改。

## 论文两遍法与工程准入

第一遍聚焦论文动机、方法输入输出、公式、实验、局限与原文证据；真实开放式问答和教师批改分角色归档。第二遍聚焦代码、配置、数据、运行入口和实验协议；只有用户/教师批准衔接才开始，不因创建目录或静态检索就记为完成。

论文学习、理解验收、代码精读、模型工程执行是不同状态轴。模型安装、前向、评估、训练需单独有界授权和资源/许可准入。学习完成不是成功复现；失败/无效run保留原因，不能为好看删掉。

## 每次结束的交付清单

1. 更新唯一正式笔记；仅有新增概念时增量维护宝典，保留公式、表格和原图来源。
2. 归档真实题目、用户原答、教师批改、补答与最终结论；缺原文标Evidence Missing，不生成历史对话。
3. 更新阅读/研究日志，区分真实发生日期、归档日期与本轮审查日期。
4. 若有授权工程执行，用唯一run关联代码SHA、数据/配置/权重、环境、命令、退出码、原始日志与结果；无执行明确Not Run。
5. 依据证据更新[当前状态源](maintenance/RESEARCH_STATUS.json)，教师未验收不得自动通过；同步首页摘要。
6. 写下一步任务及阻塞，不自动跳入后续论文/训练。
7. 先查Git状态、保护已有修改，显式暂存本轮路径并审查；按授权推送整理分支，main合并另核。
